Project 02 / Application delivery

Kubernetes CI/CD platform

A Dockerized Python web API with health endpoints, Kubernetes manifests generated by Helm, and an automated GitHub Actions quality pipeline.

DockerKubernetesHelmGitHub ActionsPythonFlask

The challenge

Reliable releases depend on more than containerizing an application. Teams also need repeatable quality checks, predictable deployment configuration, and a way to distinguish a container that is running from one that is ready to receive traffic.

This project packages a small Flask API, defines health endpoints, and captures the delivery workflow in GitHub Actions and Helm.

The architecture

Each source push or pull request starts an automated workflow that installs application dependencies, runs Python unit tests, builds a Docker image, validates the Helm chart, and renders Kubernetes YAML. A separate manual release workflow can publish the image to GHCR and use Helm to deploy it to a configured cluster.

The chart defines a two-replica Deployment and a private ClusterIP Service. Kubernetes readiness and liveness probes call separate endpoints on the API. Helm supplies versioned release configuration.

Engineering decisions

  • Principle of least privilege: containers run as non-root, drop Linux capabilities and do not mount a service-account token.
  • Traffic-aware rollouts: readiness probes help keep not-ready containers out of Service endpoints.
  • Small resource footprint: memory and CPU requests and limits are declared explicitly.
  • Portable design: local kind deployments use the same Helm chart as a cluster connected to a registry.

Repository walkthrough

Architecture, expressed in code.

Rather than storing separate YAML copies for each environment, a Helm chart provides reusable templates. Container hardening and probes are defined as part of the Deployment.

charts/cloud-web-api/templates/deployment.yaml · probes
readinessProbe:
  httpGet:
    path: /readyz
    port: http
livenessProbe:
  httpGet:
    path: /healthz
    port: http
securityContext:
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true

Browse app/ for the API, Dockerfile for the image, charts/cloud-web-api/ for Kubernetes templates, and .github/workflows/ for CI and the manually initiated release workflow.
